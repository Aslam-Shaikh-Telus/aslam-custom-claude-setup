# Documentation Practices

Apply these rules when producing documentation.

- **Don't create docs unless asked** — Never create README.md, CHANGELOG, or documentation files unless explicitly requested, or named on the `Repo docs:` line of an approved plan's `## Documentation` section.
- **Write for the audience** — Tailor documentation to its readers (end users vs developers vs ops).
- **Examples over theory** — Include concrete code examples and usage snippets. Show, don't just tell.
- **Keep it scannable** — Use bullet points, tables, and headers for readability even when being detailed.
- **Document the why** — Explain *why* decisions were made, not just *what* exists. The code shows the what.
- **Accurate code references** — When referencing code in docs, verify file paths, function names, and line numbers are current.
- **Mermaid for diagrams** — Use Mermaid syntax for diagrams when visual representation helps understanding.
